按《功能模块设计》的**系统级模块划分**重建的应用外壳，按模块逐个交付。

## 演示数据的版本（重要）

演示数据会持久化在浏览器 localStorage 里，**旧数据会盖住新种子**。
原型里加了种子版本校验：`mock.js` 的 `SEED_VERSION` 与本地记录不一致时，
自动清掉本地数据、重新灌种子 —— 这样"同一份原型在两台机器上不一样"就不会再出现。

> 这个机制是踩坑后补的：有一次评审反馈"好多卡片没显示来源任务"，
> 排查发现 25 张卡在真实 DOM 里全都有，问题出在**浏览器里存的是几轮之前的成果数据**
> （"每部成果必须关联编研任务"这条加入之前存的 24 部成果，其中 21 部 `taskId` 为空）。
> 因此**改动种子数据时务必同步把 `SEED_VERSION` 加一**。
>
> ℹ️ **任务进展不会被种子更新冲掉**：任务卡片的"推进到第几阶段 / 状态 / 阶段史"记在单独一个键
> （`archive-proto-system:taskProgress`）里，**种子版本变化时不清它**，所以更新演示数据不会把
> "我把任务推到第 3 阶段"退回去（只有手动点「重置演示数据」才清）。详见缺陷日志第 39 条。
>
> ⚠️ **看不到新种子数据时先硬刷新**（`Cmd/Ctrl + Shift + R`）：`file://` 下浏览器会缓存 js，
> 种子变了但页面还在跑旧 `mock.js`，看起来就像"功能没做"。侧边栏页脚显示了**当前种子版本**
> （如「种子 2026-09-25.1」），对不上就是读到了缓存；`index.html` 里的资源引用也加了 `?v=`，
> **改前端文件后记得同步改 `?v=`**（否则改动不会生效）。
>

页面排布上的两个约定：

- **页面标题只出现一次**（顶栏）。工作台顶部不再有独立标题块，"刷新数据"入口收进顶栏右侧的图标按钮，
  数据口径截止时间放在页尾数据说明里。
- **指标卡只保留核心信息**（图标 + 名称 + 数值）。环比与口径备注两行已按要求移除；
  `mock.js` 里的 `delta` / `note` 字段**保留但不再渲染**，需要时在 `pages/workbench.js` 的 `statCard()` 加回两行即可。
- 工作台整体采用**紧凑排布**：整页由单一变量 `--wb-gap`（12px）控制间距 ——
  页面内边距（上下左右）、区块之间、栅格列之间、卡片内边距**全部同值**，避免"外松内紧"或间距忽大忽小；
  同时 `max-width: none`、左右 `margin: 0`，保证任何窗口宽度下左右留白都恰好是一份 12px。
  实测：左内边距 12 / 顶部到首块 12 / 指标行→图表行 12 / 图表行→进度分布 12 / →待办行 12 / →数据说明 12 / →页底 12。
  见 `css/shell.css` 的 `.page-compact` 与 `.wb` 段。

图表颜色的约定：同一「编研类型」在两张图中使用**同一颜色**，避免读者在图例间反复对照；
两张类型图**行序一致**（同一行 = 同一类型），可以"横着看"同一类型的任务数与成果数；
统计数值互相自洽（类型合计 = 任务总数 32、成果总数 24；状态合计 = 32；阶段合计 = 进行中 14）。

**为什么这两张图用条形图而不是饼图**：11 类远超饼图 5–6 类的可读性上限 ——

换成横向排序条形图后：类名完整可读、条长可直接比较、数值就在行内，卡片反而更矮。

1. **配色与「任务进度分布」图一致** —— 三张条形图统一用主题强调色（`--accent` #0369a1），

   （占比列已按要求去掉；`charts.bars()` 的 `showPct` 仍可单独开启，版式不受影响）；
4. 类别多时行距自动压缩（`.bar-list-dense`），11 行的卡片高度与原先 5 行图例相当。

**三个实现要点**：

1. **全屏层挂在 `#overlay-root` 里**，不参与主应用的整页重渲染 —— 否则编辑正文时任何一次 notify 都会把工作台冲掉、光标丢失。

   代价：重新生成大纲后标题可能与已写正文错位（id 不变）—— 记在待确认里。
3. **左栏一栏两用**（评审要求）：大纲导航与素材区合并到 20% 的左栏，用分段控件切换 ——
   两处都要用的状态（当前章节 / 当前文件 / 筛选）留在模块 state 里，切页签只是重画左栏，
   所以"切过去再切回来"不会丢当前章节与已打开的文件；中栏的文件浏览也因此在切页签后保持原样。
4. **折叠不能 `display:none`**：栅格项一旦不参与布局，后两栏会被挤到前两条轨道上（中间栏塌成 0 宽）。
   改成"留在网格里 + 0 宽轨道 + `overflow:hidden`"（见缺陷日志第 20 条）。

**实现上的两个关键约束（都踩过）**：

1. **文本输入不能触发整页重渲染**。全站是"store 一变就 `render()` 整页重画"，
   若标题/内容说明每敲一个字都走 `notify()`，光标会立刻丢；更隐蔽的是
   **按钮点击会被吃掉**：`mousedown → blur → change → 重渲染 → click 落在已被摘除的元素上`。
   因此文本编辑走"input 时就地改活对象 + `silent` 落库（不 notify）"，失焦（change）时
   才记一步撤销，并用 `paintHistUI()` 手工同步撤销按钮与计数那一小块 UI。
2. **"生成中"的逐行动画只重画思考区**。`setTimeout` 逐行往 `#ol-thinking` 里写，
   生成结束才 `notify()` 整页重渲染 —— 只为一处动画破坏渲染模型不划算。

**四条原型假设（需要确认）**：

1. **AI 是预置的**：大纲由 `mock.js` 的骨架 + 提示词派生（提示词只影响"内容说明"的写法轮换，
   命中同义词时才改标题）。接真实模型时替换 `mock.outline.build / regenerate` 两个函数即可，
   页面与数据结构不用动。
2. **重新生成的粒度**：当前"重新生成当前标题"= 按同义词改写标题 + 重写内容说明；
   "重新生成子标题"= 该标题及其**全部后代**（含孙标题）。层级与编号始终不变。
3. **撤销 / 恢复只管大纲内容**（标题 + 内容说明），不含提示词、思考过程、折叠状态 ——
   Word 的撤销也不会撤销"窗口布局"。**刷新页面后撤销栈清空**（它只存在内存里）。
4. **一个任务一份大纲**，没有版本历史；重新生成即覆盖（覆盖前会记一步撤销，可回退一次）。

**顺带修的一处顺序问题**：这轮给"清空"接动作时发现，`插入 / 删除 / 拖动` 三处都是

**成果发布审核通过 → 自动归档（评审要求）**：

| 归档材料 | 材料类型 / 所属阶段 | 格式 | 内容来源 |
|---|---|---|---|

| 素材目录 | 选材材料 / 确定选材 | PDF（目录表） | 由该任务「确定选材」的**选材库派生目录表**（题名/档号/门类/来源/选入范围/页数），**不含素材文件** |

实现要点：
· 触发点在数据层 —— 发布流程**终审通过**时调用 `store.autoArchiveProduct()`；
  打开页面与「重置演示数据」后另有 `syncPublishedArchives()` 给"已完成且已登记成果"的任务补齐
  （种子里早年的成果没走过这条新链路，补齐后各任务的归档口径才一致）。
· **幂等**：同一任务同一类材料只补一次（用 `autoKey` 认人），重复同步不会翻倍；人工改过的条目不覆盖。
· **与既有过程材料合并，不出现两行同类材料**：种子里的「选题可行性评估表」并成「…及附件」、
  「选材清单（含档号与出处）」并成「素材目录」、「成果正式文件」并成「编研成果定稿」；
  附件也**不会单独占一行**。
· 自动归档的条目在列表里标「**自动归档**」（悬浮显示来源流程与成果编号），「查看」里能看到
  全部著录字段 + 附件清单 + 素材目录整张表 + 「修改这条材料」入口。

**归档材料怎么来的**：设计文档没写归档材料由谁产生，这里按编研过程生成 ——
**立项 3 件**（选题可行性评估表、立项审核批复、编研任务书）+ **每个已完成阶段 2 件**
（大纲/讨论记录、选材清单/史料说明、送审稿/校勘记、审校记录/定稿、成果文件/归档说明），
发布审核通过后再按上表补四类。归档人取该任务的**材料归档人员**，成果文件的**格式与密级取自该任务的编研成果**。

**配置驱动的落点**：字段字典 14 项（材料名称、材料类型、所属阶段、文件格式、页数、份数、载体类型、
形成日期、归档日期、归档人、保管期限、密级、电子文件号、备注），默认启用 9 项。
「归档设置」里改这份配置，材料归档的**列**与**新增/修改表单**同时跟随（验证脚本断言了这条链路）。

过程中修掉的真实缺陷（都是自动化断言或截图发现的，不是"看着差不多"）：

1. `history.replaceState` 在 `file://` 下（origin 为 `null`）会抛 `SecurityError`，导致未登录时跳转登录页失败 —— 已加 `try/catch` 回退为直接改 hash。
2. 条形图的填充元素是 `<span>`，默认 `display:inline`，`height:100%` 被忽略，进度条**渲染为 0×0**（断言查不出来，是看截图发现的）—— 已改为 `display:block`。
3. 两张类型图各自按自身数值排序，导致同一类型落在**不同行**，"并排对照"失效 —— 已统一行序。
4. `app.js` 的 `boot()` 里写死了 `login.register() / workbench.register()`，新模块的动作注册不上，
   表现是"点了新增没反应、筛选不生效"，且**不报任何错**（最阴的一类 bug）—— 已改为遍历 `App.pages` 自动注册。
5. **「加入素材库」按钮变成白底白字、完全看不见**（用户截图发现）：批量条上加过一条
   `.batch-bar .btn { background: var(--surface) }`（特异性 0,2,0），本意是让浅蓝条上的普通按钮用白底，
   却把 `.btn-primary`（0,1,0）的蓝底一起刷掉了，而白字来自 `.btn-primary { color:#fff }` —— 于是白底白字、对比度 1.00。
   已改为 `.batch-bar .btn:not(.btn-primary)`，并补了通用对比度断言（把旧规则注回去可复现失败，验证过断言确实能抓到）。
6. **行内「更改标签」点了没反应**：`openRetag()` 只从批量勾选里取素材 id，
   而行内按钮把 id 放在了 `data-id` 上、没有传进去，于是"有勾选就改勾选的、没勾选就什么都不做"。
   已改为 `openRetag(ids)`：行内传该行 id，批量条不传则取勾选项（且行内改标签不再清空批量勾选）。
7. **编研任务详情页整页只渲染出一个标签**：`renderDetail` 里写成了
   `d.tag !== undefined ? U.tag(...) : '' + (后续整段 HTML)` —— `+` 的优先级高于 `?:`，
   于是**整段 HTML 被吸进三元表达式的一个分支**，条件为真时全部丢弃。不报错、页面也不空白，只是少了一切。
   已改为直接渲染标签，并全项目扫了一遍同类"三元 + 字符串拼接"的写法。
8. **推进阶段后阶段面板停在旧阶段**：`state.viewStage = null` 写在了 `S.advanceStage()` **之后**，
   而 store 的 `notify()` 会**同步**触发一次渲染 —— 那次渲染用的还是旧值，面板停在旧阶段；
   而"进入下一阶段/回退"按钮只在当前阶段显示，看起来像功能消失了。已改为先清空再调用 store。
9. **第一张任务卡片比同排其它卡片高 16px、看着没对齐**（用户截图发现）：
   根因不在栅格，而在 `base.css` 的 `.card + .card { margin-top: 16px }` —— 它是给"上下堆叠的卡片"准备的，
   但在栅格里，同一行第二张及之后的卡片会带上这 16px 上外边距：栅格拉伸时它们的盒子被外边距吃掉 16px，
   于是第一张卡填满行高（233px）、其余是 217px，差值正好 16px。
   已加通用兜底 `.task-grid / .split-grid / .chart-grid > .card + .card { margin-top: 0 }`
   （工作台那处早先在 `.wb` 段单独取消过，但新页面没有覆盖到），并补了"同排卡片等高且顶部对齐"的断言。
10. **弹窗内文字被整体居中**（公共样式遗留问题，已随七步原型一并归档）：`base.css` 的工具类
   `.center { text-align: center }` 与布局类 `.overlay.center`（用 flex 居中弹窗）撞名，
   于是弹窗内的文字全部继承居中。此前一直没暴露，因为 `input/textarea` 不继承 `text-align`
   （浏览器默认 `start`），直到出现**纯文本的只读查看态**才现形。
   修正写在 `shell.css` 末尾（`.modal { text-align: left }`），不动公共文件。
   （`base.css` 的 `.center` 与 `.overlay.center` 撞名是历史遗留，公共文件不再改动，
   全站靠 `shell.css` 末尾这一条兜底。）
11. **点标题右侧的 ⋮ 没反应**（生成大纲界面，最难查的一个）：`mousedown` 时"点选标题"会刷新选中提示文字，
   提示变长/变短让工具行的**行高变了 27px**，整个大纲列表随之上移 ——
   于是 `mouseup` 已经落在别的元素上，浏览器把 `click` 派发到两者的共同祖先（`.ol-node`），
   `[data-action]` 自然收不到。定位方法是给 `mousedown`/`click` 加了捕获期日志，
   看到 `mousedown:ui:menu` 紧跟着 `click:ol-node`（两个 target 不一致）就锁定了。
   已改为工具行 `flex-wrap: nowrap` + 文字项 `white-space: nowrap` + 提示 `ellipsis`，
   并用"mousedown 前后各量一次几何"的脚本确认行高与子元素位置完全一致。
   **教训**：任何在 `mousedown` 里就地改 DOM 的操作，都必须保证**布局零位移**。
12. **新建标题后不聚焦**（与第 8 条同一个坑的第三次出现）：`insertOutlineNode()` 内部会
   `saveOutline → notify → 整页重渲染`，而我把"待聚焦的 id"写在了它**返回之后** ——
   那次渲染早就过去了。已改为在 store 调用返回后、直接在新 DOM 上 `focus()`
   （`focusTitle(id)`），并把这个顺序要求写进代码注释。
14. **大纲末尾几个标题的操作菜单显示不全，点开后"撤销/恢复"那一行还不见了**（用户截图发现）：
   两个原因叠在一起 ——
   (a) `.ol-panel` 与 `.card` 都有 `overflow: hidden`（本意是让圆角裁掉子元素的直角），
   而 ⋮ 菜单是**绝对定位弹出**的，落在面板/卡片边界外就被裁掉，列表最后两三个标题的菜单只剩半截；
   (b) `toggleMenu()` 里 `first.focus()` 会触发浏览器的"聚焦即滚入视口"，
   而 Chrome 为了露出被裁掉的菜单项会把页面往下滚 —— 于是大纲结果头部（撤销 / 恢复 / 清空）被滚出视野，
   看起来像"消失"了。
   已修：面板与这张卡片改为 `overflow: visible`，圆角由头部自己带（`.ol-panel-head` / `.outline-step > .card-head`）；
   菜单新增**向上翻转**（下方放不下且上方更宽裕时加 `.menu-up`，量的是最近的裁剪祖先，没有祖先就看视口）；
   聚焦改用 `focus({ preventScroll: true })`。验证脚本新增 3 条：末尾菜单三项全在菜单范围内且不超出卡片下边缘、
   打开菜单前后 `scrollY` 与头部位置**一模一样**、第一个标题的菜单仍然向下弹。
   教训：**任何裁剪容器里的绝对定位浮层都要么别裁、要么换边弹**；`focus()` 是隐式滚动，浮层里聚焦一定要 `preventScroll`。
16. **标签的「关联素材」数一直显示"未使用"、标签下拉显示"（undefined）"**（做「新增素材」时截图发现）：
   根因是"派生值只做了一半" —— `store.tagUsage()` 算得没错，页面也都写 `t.materialCount`，
   但 store 的 `tags()` 从没提供过这个字段，于是读到 `undefined`：
   表格走 `Number(x) || 0` 就静默变成 0（显示"未使用"），字符串拼接的则直接显示"undefined"。
   **四个界面同时错、没有一个报错**，因为 `undefined` 在 JS 里既不是异常也不是 falsy 之外的东西。
   修法：新增 `store.tagsWithUsage()`（返回带派生用量的**副本**，不污染 `tags()` 返回的内部数组 ——
   那个数组 `addTag` 要 `unshift`、`deleteTags` 要重建，不能改成副本），页面一律改走它；
   验证脚本补"用量列 = `tagUsage()`"与"5 个页面渲染文本里没有 undefined / NaN / [object Object]"。
17. **「指定页」四种输入都报"请填写页码"**（做确定选材时自己发现的）：`parsePages()` 校验的是
   `state.scopePages`，而那个变量只在**切换单选/重绘**时同步，用户刚敲进去的页码根本没进 state ——
   于是空、`abc`、`999`、`1,3,5-6` 一律报"请填写页码"，看日志还以为校验写错了。
   修法：`onOk` 里**从输入框现读**（`el.querySelector('#sel-pages').value`）再校验，
   state 只用于"切换单选后重绘时保留已输入的页码"。
   **教训**：表单校验的输入值必须"就近取"（从 DOM 或失焦时同步过的值），别指望一个只在特定时机更新的 state 字段。
18. **进度条从"静态"改回"可点"**：早先只有骨架时点它没有东西可切换，所以做成静态；
   现在逐阶段有了工作界面，"点阶段查看该阶段界面"成了回看已完成阶段的唯一入口，于是恢复为按钮，
   并明确 `aria-current="step"` 只标在**任务当前所在阶段**，回看别的阶段只用 `.viewing` 高亮 ——
   否则已完成任务会被 assistive tech 读成"当前在第 6 步"。
20. **折叠大纲导航后，中间栏塌成 0 宽**：`.cp-body.nav-collapsed` 里把导航设成 `display: none` ——
   它是**栅格项**，一旦不参与布局，后面的两栏就被自动放进前两条轨道（`0` 与 `38%`），
   于是中间栏拿到 0 宽、右侧拿到 38%。修法：不 display:none，改成"仍在网格里 + 0 宽轨道 +
   `overflow: hidden`"。**栅格里的元素"隐藏"不能从布局里摘掉**。
21. **点「重新生成子标题」有时看不出任何变化**（种子大纲上线后暴露）：原来的写法是按
   `regenSeq % 3` 轮换写法，可同一提示词生成的稿子本来就在同一个写法上，于是轮到的还是原来那句，
   `base + tail` 与原样一模一样。改成**每条都取"与它当前不同的下一种写法"**
   （先识别这条现在用的是第几种写法，再取 +1），保证每次重新生成都真的变了。
23. **点一次「预览」，加工编排工作台就整个消失了**（自己写断言时发现）：工作台最初挂在 `#overlay-root` 里，
   而 `U.mount()`（弹窗）在 `openStack` 为空时会执行 `root.innerHTML = ''` 清场 ——
   预览 / 查看弹窗恰恰是从工作台里打开的，于是把自己脚下的地板拆了。
   **更值得记的是：我上一轮那条"Esc 关掉工作台"的断言是假通过** —— 工作台早被预览清掉了，
   断言只看到"它不在了"就给了 PASS。修法：工作台改挂 `<body>`（z-index 95 < 弹层 100，弹窗仍盖在上面），
   并自己调一次 `U.initDelegation(el)`（事件委托只绑在 `#app` 与 `#overlay-root` 上）；
   同时补了一条"关掉预览后工作台原样还在（21 章导航 + 编排区都在）"的断言。
   教训：**同层的浮层不要共用一个会被清空的容器**；断言也要选"能同时为真又能为假"的量。
25. **拉手"折下去就展不开"**（做折叠拉手时遇到）：给折叠态的左栏加了 `overflow: hidden`（本意是裁掉栏内容），
   而拉手是**故意溢出到栏外**的半截按钮 —— 裁掉之后它仍有布局盒（`getBoundingClientRect()` 量得到 0–14px），
   却收不到点击。改成"只藏栏内容（面包屑与面板 `display:none`），整栏不裁"即可。
   **教训**：`overflow:hidden` 会连"故意露在外面的把手"一起裁掉，而这种失败在几何断言里看不出来。
26. **`chevron-left` 图标根本没定义**：折叠拉手用了它，`icons.render` 找不到就 `console.warn` 并退回 info 图标，
   于是展开态显示的是一个小圆圈 —— 截图里不盯着看根本发现不了。
   已补图标，并给套件加了"**全程 0 条 console 警告**"的断言：缺图标走的就是 warn，
   以后这类"画错了但不报错"的问题会被挡在门口。
28. **改分段控件样式时，把折叠拉手的样式一起删掉了**：拉手的 `.cp-nav{position:relative}` 与 `.cp-handle`
   紧挨在面包屑样式后面，我用"从面包屑注释到下一节注释"整段替换，正好把它们圈进去了 ——
   于是拉手没了绝对定位，变成一整条 288×21 的横条压在标题行下面。
   **是套件里的几何断言（宽度 ≤16px、垂直偏移 ≤2px）当场抓到的**，不是靠看截图。
   教训：按注释锚点做大段替换时，先确认区间里没有别的规则；改完立刻看几何断言。
29. **改了正则锚点的补丁"静默没生效"**：我用 Python 脚本往 `task-compose.js` 插一段辅助函数，
   锚点写的是当时记忆里的 `function entries(taskId) {...}` —— 那个函数早在大改三栏时就被改名成
   `allEntries()` 了。`str.replace()` 匹配不到就什么都不做、也不报错，于是文件"看起来改过了"，
   一跑就 `ReferenceError: isVideo is not defined`（还是套件的异常兜底抓到的）。
   修法：脚本里每个替换都加 `assert old in s`，匹配不到立刻停 —— 后面几轮的脚本都这么写。
30. **断言里写死的种子数量**：种子加一条录像素材后，`素材库 37 件`、`选材库 3 条` 这类写死的数字
   一下挂了 5 条断言。改成每个套件顶部集中定义 `const SEED = {...}`，断言一律引用它 ——
   种子再变只改一处，而不是在十几个断言里找数字。
31. **`addSelections` 把 `file.duration` 丢了**：它只重建了 `{name, size}` 两个字段，
   而"插入帧"要靠 `file.duration` 做时长校验 —— 种子里的录像带着时长所以没事，
   **从「选择素材」弹窗加进来的视频就没有时长**，时长提示与超范围校验一起失效。
   修法：`Object.assign({}, it.file, {name, size})` 保留全部文件字段，并补断言"从弹窗加入的视频仍带时长"。
32. **断言里的"包含"写成了 `indexOf(x) > 0`**：这个写法在**目标字符串恰好出现在开头**时为假 ——
   同一个坑先后踩了五次（每次都表现为"看起来明明对了却 FAIL"）。已把全部套件里 58 处统一改成 `>= 0`
   （"不以它开头"才该用 `> 0`，本仓库没有这种用法）。**新写断言一律用 `>= 0`。**
33. **进度条语义从"回看"改成"停在这一环"**（评审要求）：早先点环节只是"查看该阶段界面、
   不动任务进度"（因为逐阶段的工作界面要靠它回看）。评审明确要求"点某环节＝进展停在这里、
   后面的环节都回未开始，且不能跳过下一环"，于是：
   · `state.viewStage`（只读回看用的）整体删掉，界面永远画 `t.stage`，那条"正在查看第 N 阶段…"提示条一并取消；
   · 新增 `store.setTaskStage()`：写 stage、状态回 IN_PROGRESS、**阶段史截断到该阶段**、同步选题状态；
   · 可点范围＝"当前及以前 + 下一环"，更远的步骤置灰 + `aria-disabled`，点了给一句说明；
   · 顺带补了个边界：**未启动的任务全部锁住** —— 否则"点第 2 阶段"会绕过「⋮→启动」把任务启动（与 `advanceStage` 的门禁矛盾）。
   这次改动让**三个套件**的阶段点击流程都要跟着改（原来靠点第 1 阶段"回看"，现在那一下会真的回退任务）。
34. **去掉一个环节比"删一行数据"麻烦得多**：评审要求去掉「辅文编写」，而阶段编号是**有语义的位置**
   （`t.stage`、`stageHistory.stage`、归档材料模板的 `tpl.stage`、在建任务的阶段分布分组都用它）。
   只把 `TASK_STAGES` 里那一项删掉会留下 1,2,3,5,6 的空档，于是：
   · TASK_STAGES 重排为 1..5；旧 4 丢弃、旧 5/6 各上移一位；
   · 6 条显式任务的 `stage` 与阶段史、`history()` 生成器（1..6 → 1..5）、
     归档材料模板、在建任务的阶段分布分组全部重映射；
   · 列表卡片的进度切片（12 张 × 6）与三个套件的阶段断言（步数、锁定掩码 001111→00111）跟着改。
   改完用脚本校验"没有 `stage > 5`、没有历史里出现比 stage 更大的条目"，再从界面上核 5 个环节。
   **教训**：删环节是数据迁移，不是删显示项；先把"哪些地方存了阶段编号"列全，再动结构。
35. **把 `U.modal()` 当 Promise 用**：三个新弹窗我都写成 `U.modal({...}).then(function (ok) {...})`，
   而 `U.modal` 返回的是**弹窗元素**（没有 `.then`），于是点"确定"时抛异常 ——
   表现成"弹窗自己关了、什么都没发生"。而且就算它是 Promise，`then` 里也**没办法拦住关闭**，
   校验失败时会连弹窗一起关掉。正确姿势是 `onOk: function (modalEl) {...}`，返回 `false` 就不关
   （素材弹窗一直是这么写的）。
36. **"编辑了正文，撤销/恢复却一直置灰"**（用户反馈）：上一轮我把撤销栈的语义定成"只记编排动作"
   （插入/AI/脚注/清空），打字交给 textarea 自带的 `Ctrl+Z` —— 从"实现方便"看说得通，
   但**用户的实际预期是"我改了字，撤销就该亮"**。改法：把正文输入按**停顿分组**纳入同一个栈
   （停手 700ms / 失焦 / 切章 / 点别的动作时落地一步），并把 `Ctrl+Z`/`Ctrl+Shift+Z` 也接到这个栈上 ——
   否则原生撤销改了文本、又被 `input` 当成一次新输入记步，两套历史互相打架。
   教训：**"我实现的是什么"不等于"用户以为它是什么"**；交互上的取舍要么做成用户预期，要么在界面上说清楚。
37. **新页面的按钮"点了没反应"，一行报错都没有**：审核规则页的动作前缀我取了 `ar:`
   （audit rules），而 `archive.js`（材料归档）早就用了 `ar:new / ar:edit / ar:filter / ar:select…`，
   并且它的 `register()` 在我之后执行 —— 于是**我的处理器被静默覆盖**：按钮渲染正常、
   点击既不报错也不响应，连"0 条 console 错误"的断言都发现不了。
   改成唯一前缀 `rule:` 后立刻正常。教训：**动作名是全局命名空间**，新模块要用不会撞的前缀；
   另外"点不动"这类现象要先怀疑处理器没注册，而不是 DOM 事件没绑上。
38. **「改了种子但界面没变」——清库只清了白名单里的键**（用户反馈「三类审核都是未发现问题」）：
   `checkSeedVersion()` 清的是**早期写死的 9 个键**（topics / tags / materials / tasks / products /
   archive / users / flow / dict），而我后来加的 `:outline`、`:selections`、`:compose`、`:auditRules`、
   `:auditResults` 都没补进去。于是种子版本从 2026-09-26.1 升到 .27.1 时，任务与素材确实换了新种子，
   **但旧的编排正文（只有 n1/n2）活了下来** —— 审核引擎扫的就是这份旧正文，三类自然「未发现问题」，
   而演示稿 n3（写满错别字、纪年错误、身份证号、命中规则的内容）压根没进浏览器。
   修法：清库改成**按前缀 `archive-proto-system:` 清**（保留登录会话），新数据集只要按前缀命名就自动被清，
   不会再有下一次「漏加一个键」。同时补了两道防护：
   · 审核页在「编研成果还没有正文」时给醒目提示，而不是静悄悄地三张「未发现问题」；
   · 套件加回归断言：伪造旧版本 + 旧正文 → 刷新后必须重播种，且**三类审核都能发现问题**。
   **教训**：凡是「清单式」的实现（白名单清库、白名单重置、白名单复制字段）都会随功能增长漏项 ——
   能按前缀或约定推导的，就别手写清单。
39. **「刷新后任务阶段又回去了」**（用户反馈）：普通刷新其实能保留（存 `:tasks` 里），
   真正的原因是**种子版本一变就整体清库**——评审刚推进到第 3 阶段，我一发新种子，进展就被这次的
   重播种冲掉了。这不对：**种子是"演示素材"，而"我推到第几阶段"是用户的操作结果**。
   修法：把任务进展（阶段 / 状态 / 暂停 / 阶段史 / 起止时间）抽成**单独的覆盖层键**
   `archive-proto-system:taskProgress`，读取任务列表时套用；种子版本变化时**这个键不清**；
   启动时若发生过重播种，提示一句「演示数据已更新到种子 X；任务进展已保留」。
   同时补了两条断言：刷新后阶段不变、**模拟种子版本更新后阶段仍不变且演示数据确实换了新种子**。
   **教训**：清库这类"一刀切"操作要区分「演示素材」与「用户操作结果」，后者不该被前者的更新连坐。
40. **动作名撞名又发生了一次（`rv:` 撞 `review.js`）**：给「审核校定」主面板加状态筛选时用了
   `data-change="rv:filter"`，而 `review.js`（编研成果审核模块）**早就注册了 `rv:filter`**，
   且它的 `register()` 在我之后执行 —— 我的处理器被静默覆盖：选择筛选下拉后**什么都不发生、
   也没有任何报错**。这与第 37 条（`ar:` 撞归档模块）是同一个坑，说明"换前缀"这种靠自觉的做法不够。
   这次除了把前缀换成唯一的 `audit:`，还**从根上补了一道闸**：`U.register()` 检测重名并
   `console.warn`，而套件里本来就有"全程 0 条 console 警告"的断言 —— 以后任何撞名都会当场失败。
41. **右栏内容溢出却滚不动**（用户反馈"垂直滚动条不生效"）：三栏里右栏当时写成了
   `<div id="cal-right-wrap">` 包住整段 `<section class="cp-col">` —— 这个包装层是栅格项，
   但它**没有 flex 列约束**，于是"栅格行高 → 列 → `.cp-col-body{overflow:auto}`"这条高度链断了：
   body 的高度被内容撑开，滚动条自然不出现（`scrollHeight == clientHeight`）。
   修法：**去掉包装层**，让 `.cp-col` 直接当栅格项，右栏拆成"标题行 + 列表"两个可重画片段。
   现在 `scrollHeight 1839 > clientHeight 910`，`scrollTop` 能设住；套件里加了滚动断言。
   **教训**：`overflow:auto` 要生效，必须有一条"高度受限"的祖先链；中间多套一层不带 flex/高度的
   容器，滚动就会失效 —— 这类问题肉眼看不出来，只能靠"设一下 scrollTop 看它守不守"来断言。
42. **发布后要"能看不能改"，我第一版把"看"也一起堵死了**：给锁定任务的写操作加了数据层拦截
   （`lockedGuard`）之后，`setTaskStage` 也被拦 —— 于是点进度条换环节同样失败，
   用户**没法再查看前面几个环节的已有信息**，与评审要求"可以查看每个环节的已有信息"相反。
   修法：锁定任务里点环节＝**只读查看**（用 `state.viewStage` 当视图，不写回 store；进度永远是发布时那一步），
   并给 `setTaskStage` 保留拦截（真正的进度不允许再变）。
   **教训**：加权限/锁定这类"一刀切"拦截时，先把功能按"读 / 写"分一遍 —— 拦住写很容易顺手把读也拦住。
43. **未读角标把页面撑出 2px 横向滚动条**：`.badge { right: -2px }` 让角标越出视口，页面 `scrollWidth` 1500 → 1502。
   定位方式：遍历 `body *`，找出 `getBoundingClientRect().right > clientWidth` 的元素（一条命令就锁定了角标）。
   改成贴内侧（`top:1px; right:1px`）。
44. **审核信息表的列宽被 `rowspan` 挤坏**：人员信息那一格我顺手写了 `rowspan="4"`（样例图上确实是跨 4 行），
   但三个"人员行"其实在**嵌套表**里 —— rowspan 会跨到后面的"审核意见/备注"两行上，
   浏览器就把那两行的 `<th>` 挤到第 3 列，列宽因此错乱（名称列窄到逐字换行）。
   去掉 rowspan（嵌套表自己就有表头 + 3 行）后，表格恢复 828px 满宽。
   **教训**：`rowspan` 要和"表格里真实存在的行"对齐 —— 视觉上的跨行有时是内部嵌套表造成的，
   照着截图写 rowspan 会数错行。另外这类问题肉眼只看"像不像样例"，加一条**列宽断言**（表宽≈容器宽、
   值列占大头）才拦得住。
45. **一级标题编号少了点号**：`numbering()` 输出 `1`，与 `1.1` / `3.3.1` 体例不一致。
   已改为一级补 `.`（`1.`），并把编号支持从 3 级扩到 8 级（计数器数组按 `MAX_LEVEL` 生成）。
46. **新全屏模块的按钮"点了没反应"，而且一条报错都没有**：`topic-review.js` 只导出了
   `App.topicReview.register`，但**没有人调用它** —— 全屏模块不是 `App.pages` 的页面，boot 的
   自动注册遍历扫不到它，于是 `tpr:submit / tpr:export / tpr:pass` 全都没注册：界面渲染正常、
   点击既不响应也不报错（和第 4、37、40 条同族，只是这次连"撞名"都不是，纯粹是**没挂上**）。
   修法：在 `topic.js` 的 `register()` 里调用 `App.topicReview.register()`（`task.js` 早就用同一招
   注册五个阶段界面）。**教训**：给全屏模块加动作时，先确认"它的 register 到底被谁调用"，
   并且 `U.register` 的重名警告**发现不了"一个都没注册"**，验证套件里必须有"点一下看有没有变化"的断言。
47. **同一类流程出现两套编号前缀**：种子里两条成果审核流程是 `SH-2026-000x`（`REVIEW_FLOW_TYPES`
   写的前缀也是 `SH`），而新发起的成果流程按 `FB-` 走 —— 列表里同一类流程编号格式不一致。
   统一为 `FB-`（种子的两条也改了）；**教训**：编号前缀这类"口径"要么从一处派生，要么在改动时全局搜一遍，
   否则只在新建路径上生效。
48. **种子里"成果审核中"的任务点开审核界面，右栏显示"这个任务还没有大纲"**：`RW-2026-003` 在种子里
   只到第 4 阶段、且没有大纲与正文，而流程记录却指向它 —— 演示时右侧的"编研成果文件"是空的。
   修法：把它补成完整的第 5 阶段演示任务（大纲 10 条 + 正文 8 章 + 阶段史补到第 5 阶段），
   同时给 `T-003` 补齐立项材料（原先 `background/content/team` 全空，发起审核后右栏整张表都是「未填写」）。
   **教训**：种子数据之间有引用关系（流程 → 任务 → 大纲 → 正文），加一条"进行中的流程"就要顺带把
   被引用对象的演示数据补齐，否则界面会出现"看起来坏了"的空壳。
49. **老流程在新审核界面显示"审核人：未配置"**：`flowStepsOf()` 会把早期"单审核人"的流程兼容成一步，
   但这一步没有 `reviewers` 数组，界面判断 `s.reviewers.length ? … : '未配置'` 就落到了"未配置"，
   明明 `reviewer` 上写着姓名。修法：有角色信息才显示括注，没有就直接显示姓名（`reviewerText()`）。
   **教训**：兼容层造出来的对象也要满足界面的**全部**取用方式，不能只满足"能渲染"。
50. **全屏界面左栏标题重复**：列头已经写着「审核步骤与审核意见」，正文里又渲染了一遍同名 `h3`
   （发起态首行是"本次发起的选题"所以没露出来，审核态一打开就露馅）。审核态/查看态去掉正文标题，
   流程号改到列头右侧的说明里。**教训**：同一屏的"标题"只能有一个权威位置，测试断言也要盯着列头而不是正文。
51. **套件里 `(x || {}).textContent.replace(...)` 会抛异常**，而 `.toolbar-note` 取到的是"参与范围"这个
   标签而不是权限说明 —— 断言因此失败在"看起来元素存在"的地方。修法：取值统一加兜底
   （`|| ''`），并给当时的权限说明加了稳定选择器 `#rv-scope-note`（顺带让读屏也能定位）。
   **教训**：测试选择器要选"语义唯一"的锚点；对可选元素一律做空值兜底，别让断言挂在自己的取值上。
   后来这段权限说明与"等待你审核"提示条按评审要求整段删除，`#rv-scope-note` 一并移除，
   套件改成断言「页内提示条 0 个」+「无关流程不可见」—— 比挂在文案上更耐改。
52. **材料归档的「查看」一点就报 `fmtSize is not defined`**：文件大小的格式化函数当初写在
   `topic.js` 里（局部函数），我在 `archive.js` 里直接照着用同名函数 —— 列表能渲染，一点「查看」
   就在附件清单那里抛 ReferenceError（弹窗根本没打开）。修法：把它提到 `js/util.js` 的
   `App.util.fmtSize`，`topic.js` 的 3 处调用一起改过来。**教训**：跨模块要用的格式化/工具函数
   必须放公共层；"照着另一个页面抄一份"的写法肉眼看不出来源，只有跑到那条分支才会炸。
   另外这条是套件"全程 0 异常"的断言逼出来的 —— 只看截图会以为"弹窗没弹出来"是别的原因。
53. **「查看」弹窗里「材料名称」出现两次**：我在 `openDetail()` 里手写了一行「材料名称」，
   而字段字典的第一项也是「材料名称」—— 于是同一张表里两行同名。修法：删掉手写那行，只信字典。
   **教训**：字段字典是列表 / 表单 / 查看三处的**同一份口径**，页面里不要再手写字段行，
   否则加字段时就会出现"字典里有、手写行没有"或"重复一行"。
54. **自动归档把同类材料变成了两行**：种子里的过程材料与评审要求的四类材料口径重叠 ——
   「选题可行性评估表」vs「选题可行性评估表及附件」、「选材清单（含档号与出处）」vs「素材目录」、
   「成果正式文件」vs「编研成果定稿」，附件还会各自占一行。修法：给每类材料一个 `mergeWith` 判定，
   **能对上号的既有条目就地并成一条**（改名/改格式/挂附件/标自动归档），对不上号才新增；
   附件只作为清单挂进「…及附件」条目。**教训**：新老数据口径重叠时先定"合并还是并存"，
   否则列表上就是两行看着像重名的材料，评审一定会问"到底哪条作数"。
55. **表单提示语出现两次**：字段字典的 `hint` 既当 placeholder、又在下面渲染成一行说明，
   于是「如：编研大纲（含编写要点）」上下各一份。修法：**有 placeholder 的控件不再补说明行**
   （日期 / 数字 / 字典下拉没有 placeholder，才用说明行承载 hint）。
   **教训**：同一句提示在一个控件周围只出现一次；这类"看着啰嗦"的问题断言查不出来，靠截图复核。

## 已知取舍

- 数据全部为 mock，但**统计数值互相自洽**，避免演示时被追问"数字对不上"。
- 图表悬停只做视觉增强，分类名/数量/占比都在图例中以文本呈现，不依赖颜色传达信息。
- 图表遵循"饼图不超过 5 类"的可用性建议；阶段分布这种**有序**分类改用横向条形图。
- **AI 大纲是"看起来像"而不是"真的"**：预置骨架 + 提示词影响写法轮换 + 同义词改写标题。
  这样做的好处是演示可复现（同一提示词两次生成结果稳定、便于评审对照），
  代价是**重新生成的差异有限**（不会真的重写内容），接模型后这个取舍自然消失。
- **文本编辑不重渲染**是为了不丢光标 / 不吞点击，代价是撤销按钮与计数需要手工同步
  （`paintHistUI`）—— 这类"局部更新"多一处就多一份不一致的风险，所以只用在输入框上。
- **撤销栈只存在内存里**：刷新页面后清零（大纲内容本身是持久化的）。Word 的撤销也是这样。
- **列表分页是前端切片**：39 条数据一次性读进内存，翻页只是 `slice()`；真实系统数据量大时必须改成后端分页（接口参数 `page` / `pageSize` + 总数），前端这套分页条可以直接复用。
- **删掉一个任务不会跳页**：只有当前页被删空时才夹回最后一页，而不是每删一个就弹回第 1 页。
- **任务详情页骨架期，进度条是静态的**：点它没有东西可切换，做成可点会让人以为功能坏了；
  等步骤工作界面接回来，改回 `<button data-action="task:stage">` 并恢复 `viewing` 高亮即可
  （CSS 里 `.step.viewing` 的规则还留着）。
- **撤下的代码不删、收进 `renderDetailExtras()`**：这是"暂时不显示"而不是"废弃"，
  逐个步骤回归时按需取用；代价是这个函数当前不被调用，读代码时要靠注释判断它是**有意保留**的。
- **「发起审核」先给一张全屏"预览"再落库**：勾选 → 全屏界面（左步骤与意见 / 右评估表）→「确认发起审核」
  才真正生成流程。好处是"谁审、几步审"在发起前就写清楚了，代价是多一次点击；
  若评审希望沿用"确认框 + 一行文案"的轻交互，去掉界面里的确认环节即可（`tpr:submit` 那段）。
- **归档材料"可改可增"顺带把删除也做了**：评审这轮只要求"修改 + 新增"，但工具栏里本来就有一个
  「删除」按钮（此前是占位提示）。按"不留假按钮"的约定，这次一并实现（勾选 + 二次确认）——
  若评审认为归档材料应当**只增不删**（档案的不可否认性），把按钮撤掉、只留数据层接口即可。
- **自动归档与既有过程材料合并而不是并存**：种子里的"选题可行性评估表 / 选材清单 / 成果正式文件"
  与评审要求的四类材料口径重叠，合并后列表不会出现两行同类材料；代价是这几个旧名称在
  已完成任务里被替换掉了（材料名称以评审要求为准）。
- **导出先落 HTML**：原型没有后端，导出用浏览器本地生成的 HTML 文件（表格式与界面一致，含表题与字段值）。
  好处是离线可用、可当场打开核对；代价是不是正式公文格式 —— 生产接模板引擎导出 Word / PDF。
- 验证脚本随原型版本化（`tools/verify/`），不再写 `/tmp` —— 上一批被系统临时目录清掉，
  462 项检查一笔勾销，这个教训比脚本本身更值得留在文档里。
